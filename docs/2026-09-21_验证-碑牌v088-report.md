# v0.8.8 碑牌全量词缀与名称核对

本次按用户截图要求，将碑牌名称改为项目现有暗金装备格式，补齐总督底材价，并从真实游戏文件反查全部可生成词缀。验证使用获授权的 `D:\poe2\Content.ggpk`，包括实际写入、读回、还原和重新安装；没有启动游戏对新画面作验收。碑牌仍属于通货更新，保留岛屿传言、接口重试及独立跳过。

## 缺陷证据与修改

| 证据 | 结论 | 修复路径 |
|---|---|---|
| 图 4 与项目 `format_unique_price_name(..., 'markup')` | 暗金装备使用 `[价格\|名称]`，v0.8.7 的 `名称=价格` 不符合要求 | 原样提取 `poe2_price_labels.py`，碑牌和暗金装备导入同一格式函数与清理函数；没有两套重复实现 |
| poe.ninja 返回总督 Magic `0.3285D`、Rare `0.1189D`，没有 Normal | 上一版只允许 Normal 导致总督名称漏价 | 先取 Normal，缺失时从现有有效品质中取最低价；本次总督为 `0.12D`，报告记录 `variant=Rare`、`selection=lowest_available` |
| API 深渊“每个已关闭坑洞增加 (8–12)% 效用，最多 100%”有有效报价；游戏描述只有 `{0}` 一个变量 | 旧代码把固定上限 100 当成第二个变量，在解析阶段丢弃了该报价 | 保留接口行，按游戏占位符定位变量，逐项核对固定数字；生成 `8\|12` 价格分支，繁中本次为 `最多100%=0.61D` |
| 总督两条额外神殿报价分别覆盖 1 和 1–2，同值分支只选较低报价 | 不能把被另一有效低价覆盖的报价算作遗漏，也不能在未生成分支前计成功 | 在实际输出分支后记录所有被覆盖报价，重叠范围继续使用最低有效价 |
| 新格式仅修改名称时可能没有 IT 继承变化 | 旧的补丁检测只比较继承指针，会漏掉仅名称标价 | `export_names` 比较碑牌名称与继承清理结果；关闭、失败、缓存回退及还原共用标记清理 |

上一版“253 条已匹配”的结论基于解析后列表，漏掉了解析阶段被丢弃的深渊词缀。本版增加从游戏 `Mods / Stats / Tags / BaseItemTypes` 出发的独立完整性核对，覆盖接口统计之外的范围。

## 全量游戏文件核对

从当前真实客户端提取三张表，验证固定行宽分别为 Mods 693、Stats 106、Tags 44。筛选 ModDomain 34、GenerationType 1/2，按底材标签与顺序生成权重确定可以出现的词缀，再从每类安装 CSD 按首次匹配规则选择实际显示分支。每个词缀检查游戏最小值至最大值的全部整数，不只检查端点；两种中文分别检查，确认 IT 同时启用魔法和稀有。

| 底材 | 可生成词缀组合 | 名称价格 |
|---|---:|---:|
| 裂痕 | 31 | 41.5E |
| 探险 | 37 | 0.13D |
| 谵妄 | 33 | 23.7E |
| 祭祀 | 33 | 0.38D |
| 辐照 | 24 | 0.37D |
| 总督 | 32 | 0.12D |
| 深渊 | 33 | 0.66D |
| 神庙 | 31 | 0.54D |
| 合计 | **254** | **8 类全部标价** |

结果：90 个不同游戏词缀，254 个可生成的底材与词缀组合，12,964 个数值、语言、稀有度检查全部通过。五个词缀的附加属性为 0，不产生描述；探险的额外 `expedition_elite_pack_size_+%` 固定属性在当前三份描述资源中均无显示行，不能当作可见漏价词缀。固有“剩余使用次数”和底材效果描述不属于可交易随机词缀。

名称价为每种底材的统一市场参考；缺普通报价时取其他品质报价不代表已经取得白装成交价，也不是按当前物品品质动态估价。词缀行情采用数据源自身查询条件，各词缀价不可相加作为整件估值。
