# 开发说明

本分支是 POE1 / POE2 双版本物价补丁，支持：

- POE1/POE2 国服 WeGame Bundles2
- POE1/POE2 国际服官方独立端 GGPK
- POE1/POE2 国际服 Steam/Epic Bundles2

## 双版本隔离

- 统一 GUI 可选择 `poe1`、`poe2` 或 `auto`；自动识别会先判断客户端格式，再通过路径、可执行文件和 Bundle 内容识别版本。
- POE1 使用 `build_poe1_price_patch.py` 和 POE1 专用 PowerShell 入口，价格单位为 C/D；国际服抓取 poe.ninja，国服抓取 `poecurrency.top/api/summary?version=1` 并用 poe.ninja / poe2scout / poedb 补缺。
- POE2 继续使用 `build_poe2scout_price_patch.py` 和原有 E/D 规则。两版分别使用 `output/poe1`、`output/poe2_price_patch_latest`、独立缓存和还原包，不会互相覆盖。
- POE1 的 BaseItemTypes/Words 处理支持当前 POE1 DAT 布局，Bundles2 与 GGPK 提取接口由 BundleExtractor 统一提供。
- POE1 国际服可从统一 GUI 点击“一键汉化POE1国际服”。`localize_poe1.ps1` 从 GitHub Releases API（经 `gh-proxy.com` 或官方 API）读取最新正式版本、官方文件大小和 digest；API 不可用时，再经 `ghfast.top`、`ghproxy.net`、`gh.ddlc.top`、`ghproxy.it`、`github.boki.moe` 或 GitHub 官方 Release 页面读取标签与公布的 SHA256。程序本体按 `ghfast.top`、`gh-proxy.com`、`gh.ddlc.top`、`ghproxy.it`、`github.boki.moe`、`ghproxy.net`、`gh.jasonzeng.dev`、`gh.monlor.com`、GitHub 官方源依次切换，下载后校验长度（API 可用时）、SHA256、PE/产品版本再执行。`bdnb.cn` 因高速通道需要交互密码、匿名通道严重限速而未接入；Gitee 暂无可验证的具体镜像仓库。GUI 使用隐藏子进程和重定向日志，每 200 毫秒处理一次窗口消息并显示运行秒数/最新阶段，超时清理整个子进程树；不再计算完整 `Content.ggpk` / `_.index.bin` 的前后 SHA256。完成后使用 `language=fr`（游戏内第二个法文国旗）。国服目录会被拒绝，汉化不复用旧下载缓存。

## 数据源

本工具不使用官方 Trade 接口。

- POE2 国际服通货和普通可交易分类主源是 poe2scout `SnapshotPairs`，备用 poe.ninja 与 poe2db Economy；传奇护甲单独以 `https://poe.ninja/poe2/economy/forbiddenrites/unique-armours` 背后的 `stash/current/item/overview?league=<当前赛季>&type=UniqueArmours` 为优先源。
- POE2 国服主源是 `poecurrency.top/api/summary?version=2`。
- POE1 国际服主源是 poe.ninja；POE1 国服主源是 `poecurrency.top/api/summary?version=1`。
- `audit_price_sources.py` 同时审计 POE1/POE2 实时契约，对照 `data_source_contract_baseline.json`。
- 每次 POE2 构建会读取 scout `Items/Categories`：新传奇分类会继续抓取并写入健康告警；ninja 未覆盖的通货分类只报警，不自动扩 type。UniqueArmours 读取 `core.primary` 决定单位，Exalted 不再重复换算，过滤腐化、零挂牌和无效价格，并对同名多底材行做确定性去重。
- 捆绑 Python 通过 `poe_python.exe` 以 `RunAsInvoker` 启动，避免本机 `python.exe` 被勾选“以管理员运行”后出现 740 提权失败。

## 国服 OCR 报价校验

POE1、POE2 共用 `price_sources/poecurrency_pricing.py`，只使用普通 `api/summary` 返回的字段；不请求 Token 校验接口或逐笔历史接口。算法不会增加玩家操作。

- 买、卖两侧分别与自身历史比较。12 小时均价和 `buy_avg` / `sell_avg` 作为同一组候选，24 小时均价和昨日均价作为另一组，避免重复字段重复投票；买侧另参考上一笔报价。已提供时间戳且相隔超过 24 小时的上一笔不参与计算。
- 历史候选先选数量最多、彼此差距在阈值内的一组，再取对数空间的中位数；偶数个候选取中间两项的几何均值。普通物品阈值为 3 倍，影响全局换算的神圣石为 2 倍。当前价超过阈值时弃用该侧，另一侧正常则用另一侧，两侧都不可用才采用历史估值。
- `error` 是辅助信号。当前价有历史支持时，9→10 等正常跨位数变化仍可使用；只有错误标记且没有历史依据的当前价不直接使用。非法数字、非有限值和超出算术边界的数值不参与定价。
- D 单位保留小数点丢失修正：低侧为小数、高侧为整数时，需要低侧历史支持，且缩放 10 / 100 倍后相差不超过 1.5 倍。兼容旧 OCR 样例中均价被两种数量级混合污染的情况，但仅允许两侧弱历史都处于高低数量级之间的 100 倍修正，并记录 `mixed_scale_history`。该修正是启发式估计，不能视为成交真值。
- 校验后两侧都有价、差距不超过 5 倍时取几何均值；持续宽价差不再一律取低侧，优先买一并标记 `wide_spread`。神圣石优先使用校验后的买一。国服 D/E、D/C 必须使用国服汇率，国际汇率不能补代；显式 `e` 派生字段也需与已校验价格一致才能采用。
- 国际参考仅补缺和记录差异，不因差价大就覆盖已有国服报价。`high_value_reference_items` 保持为 0，差异数量写入 `high_value_reference_warnings`；详细原因写入报价的 `source_pair`、POE2 的 `quality_flags` 及汇总的 `pricing_reasons` / `price_flagged_items`。带标记数量不等于已确认错误数量。

汇总接口没有完整时间序列和成交凭据。如果当前价与所有历史字段同时被污染，无法保证识别；真实行情突然变化超过阈值也可能暂时采用历史估值。新赛季无历史字段时保留无错误标记的有效当前价，不借用其他赛季数据。

相关离线回归可执行 `python -m pytest tests/test_cn_summary_guard.py tests/test_poecurrency_pricing.py tests/test_poecurrency_quality.py tests/test_poe1_support.py -q`。

## 更新流程

1. GUI 提供自动识别和手动选择。自动识别依次考虑补丁文件夹上一级、环境变量、最近有效目录、卸载项、WeGame/Steam 游戏库、Epic 清单和常见目录；多个非明确候选会要求手动选择。CLI 仍可用 `-Poe2Dir` 显式指定。
2. 目录候选必须包含 `Content.ggpk` 或 `Bundles2\_.index.bin`；国服名称兼容“流放之路：降临”，并通过 WeGame/Rail/Tencent 文件特征判定。最终目录会保存到 `%LOCALAPPDATA%\Poe2PricePatch\settings.json`，失效记录自动忽略。
3. `Get-Poe2InstallInfo` 检测安装类型和目标语言资源，随后获取真实游戏目录级互斥锁，防止不同补丁副本并发操作同一客户端。
4. 提取英文 `data/balance/baseitemtypes.datc64`。
5. 提取目标语言 `BaseItemTypes.datc64`：
   - 国服：`data/balance/simplified chinese/baseitemtypes.datc64`
   - 国际服：读取 `poe2_production*_Config.ini` 的 `language=` 后选择对应语言文件；例如繁中为 `data/balance/traditional chinese/baseitemtypes.datc64`，英文为 `data/balance/baseitemtypes.datc64`
6. 提取英文 `Words.datc64`、目标语言 `Words.datc64` 和 `UniqueGoldPrices.datc64`，用于识别传奇物品名并清理旧版传奇标价。
7. `build_poe2scout_price_patch.py` 按客户端类型抓取价格：国际服通货和普通分类优先 poe2scout，poe.ninja / Poe2DB 按备用链路补齐；传奇护甲优先读取 poe.ninja UniqueArmours JSON，运行时将页面配置转换成当前赛季 `league` 参数，缺失或无效时才由其它来源补缺。国服 WeGame 优先使用 `https://poecurrency.top/api/summary?version=2`，没有国服数据的普通物品和传奇装备再用国际参考源兜底。当前软核赛季默认从 poe2scout `/poe2/Leagues` 自动发现。普通物品写目标语言 `BaseItemTypes.datc64`。传奇 Words 标签必须按游戏代数选择：POE1 默认 `传奇名[<<价格>>]`，当前易刷 POE1 解析器删除行尾方括号；POE2 默认 `[价格|传奇名]`，当前易刷 POE2 解析器用 `\[[^|\]]*\|` 保留竖线后的名称。PoE Overlay II 同时兼容两种格式。交叉使用会回归：POE1 会把整行竖线标记删空，POE2 会把后缀标记清成 `传奇名<>`。
8. D/E 换算比例实时从当前数据源推导：国际服读取 poe2scout，国服读取 poecurrency.top 中“神圣石”的当前价格；读不到比例时中止生成，避免使用固定比例。
9. 国服按上文“国服 OCR 报价校验”验证普通汇总接口的最新报价、上一笔和历史均价，异常侧不直接参与定价；`engname` 仅在中文名无法匹配时补匹配。
10. 每个数据源都写入统一健康与 schema 指纹报告；`audit_price_sources.py` 仅直接请求实时数据并写 JSON，不读写游戏文件。
11. 所有价格文件先在隔离目录生成并校验，再原子发布。完整数据失败时先降级为核心层，再尝试与当前客户端、语言、勾选范围和构建模式匹配的最近成功缓存；缓存安装时只保留通过结构签名检查的 BaseItemTypes，不复用旧 Words/EndgameMaps。都不可用时停止本次更新，不修改游戏。
12. 按格式安装，写入前复核 Bundles2 并发指纹，写入后提取目标 DAT 核对长度和 SHA256；失败时自动使用已验证还原包回滚：
   - GGPK：`PatchBundledGGPK3.dll`
   - Bundles2：`PatchBundle3`

POE1/POE2 的 Bundles2 英文表和本地化表必须通过同一次 `BundleExtractor --extract-list` 批量提取，英文 `BaseItemTypes` 是实时构建必需项；如果索引短暂被 Steam/WeGame/杀毒软件占用，提取器会有限重试，避免连续启动原生提取器造成 `_.index.bin` sharing violation。游戏更新会覆盖已写入的虚拟资源，因此用户仍需在更新完成后重新运行；脚本始终从当前索引提取底板并校验结构，不绑定固定赛季 DAT。

## 同名元数据匹配

`BaseItemTypes` 允许多个元数据路径复用同一个英文或本地化显示名，例如普通物品与任务别名。价格匹配必须保留名称索引中的全部候选，并为每个候选生成一行补丁；不能使用单值字典让后出现的路径覆盖前一条。

国服数据优先按本地化名称匹配。若多个英文物品共用同一翻译，则使用数据源提供的 `engname` 过滤候选；没有足够英文信息时只保留安全的单一候选，避免跨物品串价。修改匹配逻辑时，应同时更新 `物价补丁/tools/build_poe2scout_price_patch.py` 及对应测试。

Issue #23 的官服回归检查使用最新版 `Content.ggpk`：修复前匹配 565 行，修复后 582 行；`Head of the King`、`Kulemak's Invitation` 和三种 Crisis Fragment 的重复元数据路径均生成价格，缺失列表为零。

## 还原流程

未显式传入 `-Poe2Dir` 时，还原器与更新器一样先显示目录选择窗口，并复用最近一次有效目录。确认后获取真实游戏目录级互斥锁；更新器内部触发自动回滚时会显式跳过子进程重复加锁，由父更新流程继续持有同一把锁。

Bundles2 模式更新前会生成 `真实还原物价补丁.zip`，备份当前 `Bundles2` 关键物理文件：`_.index.bin`、`_.index.high.bin`、`_.index.low.bin`、`.index.dbg` 和当时存在的 `LibGGPK3`。还原时首先验证并使用这个物理备份包，不要求先准备 .NET；替换后会核对精确文件集合，失败则自动恢复操作前状态。

普通 `还原物价补丁.zip` 仍会生成，用于记录干净 BaseItemTypes 和 Words 内容，但 Bundles2 真实还原不再用 PatchBundle3 写回这些资源来冒充还原。生成或刷新还原包时会拒绝带传奇价格标记的 `Words.datc64`，包括旧版独立行、POE2 当前 `[价格|传奇名]`、Overlay 专用 `<<[价格]>>` 和 POE1 当前 `传奇名[<<价格>>]` 后缀标记。

GGPK 模式如果没有干净还原包，不从当前已修改 GGPK 反提取还原包，避免污染备份。GGPK 与 Bundles2 逻辑还原都会读回目标 DAT 校验；逻辑写入校验失败会自动重试一次。

## 碑牌参考价与资源安装

`poe2_tablet_prices.py` 在 POE2 通货范围内读取碑牌词缀 API 与 poe.ninja `PrecursorTablets`。两源独立重试和降级，API 快照、赛季、汇率及分页必须一致。价格按词缀数值范围写入独立 CSD 分支，未覆盖数值保留原文；底材按普通、魔法、稀有分列，避免混用整件价格。模板来自当前游戏，不修改共用模板。

魔法与稀有碑牌使用完整的同一套词缀标价规则。单数和复数分支均需覆盖，按首次匹配条件检查范围端点，不能只看英文文本是否匹配；`canonical_line` 是描述元数据，不是数值变换。缺少某种中文译文时使用资源内另一中文译文，不生成市场数据中没有的报价。

`poe2_tablet_refs.py` 只识别 8 个已知碑牌行及对应自家模板，清理旧实验和当前价签引用，并验证 ZIP 引用的 IT/CSD 完整。BaseItemTypes 结构签名 v2 只对这组已知继承重定向规范化，其他固定字段仍严格比较。英文表和目标语言表均须处理。

`BundleExtractor` 的 `--patch-ggpk` / `--patch-bundles` 会先生成独立 bundle 与新索引，比较全部原文件记录，确认无关映射不变，再独占写入并读回全部目标。新增路径仅允许 8 类碑牌的 16 个 IT/CSD 文件。事务目录保存当前版本的前后索引及文件 SHA256；重复相同内容不会写入。旧未引用 bundle 保留，避免删除其他补丁资源。

真实 GGPK 验证记录见 [v0.8.6 碑牌修复验证](2026-09-21_验证-碑牌v086-report.md)。Bundles2 使用真实资源副本验证，未声称进行 Steam 客户端或游戏内画面验收。
