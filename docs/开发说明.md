# 开发说明

本分支是 POE1 / POE2 双版本物价补丁，支持：

- POE1/POE2 国服 WeGame Bundles2
- POE1/POE2 国际服官方独立端 GGPK
- POE1/POE2 国际服 Steam/Epic Bundles2

## 双版本隔离

- 统一 GUI 可选择 `poe1`、`poe2` 或 `auto`；自动识别会先判断客户端格式，再通过路径、可执行文件和 Bundle 内容识别版本。
- POE1 使用 `build_poe1_price_patch.py` 和 POE1 专用 PowerShell 入口，价格单位为 C/D；国际服抓取 poe.ninja，国服抓取 `poecurrency.top/api/summary?version=1` 并用 poe.ninja 补缺。
- POE2 继续使用 `build_poe2scout_price_patch.py` 和原有 E/D 规则。两版分别使用 `output/poe1`、`output/poe2_price_patch_latest`、独立缓存和还原包，不会互相覆盖。
- POE1 的 BaseItemTypes/Words 处理支持当前 POE1 DAT 布局，Bundles2 与 GGPK 提取接口由 BundleExtractor 统一提供。
- POE1 国际服可从统一 GUI 点击“一键汉化POE1国际服”。`localize_poe1.ps1` 每次优先通过国内 `ghfast.top`、`gh-proxy.com` 加速源查询并获取 PoEDB 中文化说明指向的 LibGGPK3 最新 Release，失败后回退 GitHub 官方源；下载后校验 PE/产品版本，并将 SHA256 与 Release 页面公布值比对后再执行。完成后使用 `language=fr`（游戏内第二个法文国旗）。国服目录会被拒绝，汉化不复用旧下载缓存。

## 更新流程

1. GUI 提供自动识别和手动选择。自动识别依次考虑补丁文件夹上一级、环境变量、最近有效目录、卸载项、WeGame/Steam 游戏库、Epic 清单和常见目录；多个非明确候选会要求手动选择。CLI 仍可用 `-Poe2Dir` 显式指定。
2. 目录候选必须包含 `Content.ggpk` 或 `Bundles2\_.index.bin`；国服名称兼容“流放之路：降临”，并通过 WeGame/Rail/Tencent 文件特征判定。最终目录会保存到 `%LOCALAPPDATA%\Poe2PricePatch\settings.json`，失效记录自动忽略。
3. `Get-Poe2InstallInfo` 检测安装类型和目标语言资源，随后获取真实游戏目录级互斥锁，防止不同补丁副本并发操作同一客户端。
4. 提取英文 `data/balance/baseitemtypes.datc64`。
5. 提取目标语言 `BaseItemTypes.datc64`：
   - 国服：`data/balance/simplified chinese/baseitemtypes.datc64`
   - 国际服：读取 `poe2_production*_Config.ini` 的 `language=` 后选择对应语言文件；例如繁中为 `data/balance/traditional chinese/baseitemtypes.datc64`，英文为 `data/balance/baseitemtypes.datc64`
6. 提取英文 `Words.datc64`、目标语言 `Words.datc64` 和 `UniqueGoldPrices.datc64`，用于识别传奇物品名并清理旧版传奇标价。
7. `build_poe2scout_price_patch.py` 按客户端类型抓取价格：国际服优先 poe2scout，poe.ninja / Poe2DB 按备用链路补齐；国服 WeGame 优先使用 `https://poecurrency.top/api/summary?version=2`，没有国服数据的普通物品和传奇装备再用国际参考源兜底。当前软核赛季默认从 poe2scout `/poe2/Leagues` 自动发现。普通物品写目标语言 `BaseItemTypes.datc64`。传奇物品默认写入兼容标记 `[价格|传奇名]`：PoE Overlay II 和易刷在解析 `Ctrl+C` 文本时都会把它清洗回原始传奇名，避免价格污染 `name` 查询字段，同时游戏内只显示一次传奇名。
8. D/E 换算比例实时从当前数据源推导：国际服读取 poe2scout，国服读取 poecurrency.top 中“神圣石”的当前价格；读不到比例时中止生成，避免使用固定比例。
9. 国服优先使用 `latest_buy1` / `latest_sell1` 取最新盘口价，缺失时再回退到 `buy_avg` / `sell_avg`：两边都有值且价差不超过 5 倍时取几何均值，价差超过 5 倍时取较低一侧，避免过期均价、OCR 异常或极端盘口把价格拉偏；只有单边有效时使用单边价格。`engname` 仅在中文名无法匹配时补匹配，昨日均价仅在现有候选全部无效时兜底。
10. 每个数据源都写入统一健康与 schema 指纹报告；`audit_price_sources.py` 仅直接请求实时数据并写 JSON，不读写游戏文件。
11. 所有价格文件先在隔离目录生成并校验，再原子发布。完整数据失败时先降级为核心层，再尝试与当前客户端、语言、勾选范围和构建模式匹配的最近成功缓存；缓存安装时只保留通过结构签名检查的 BaseItemTypes，不复用旧 Words/EndgameMaps。都不可用时停止本次更新，不修改游戏。
12. 按格式安装，写入前复核 Bundles2 并发指纹，写入后提取目标 DAT 核对长度和 SHA256；失败时自动使用已验证还原包回滚：
   - GGPK：`PatchBundledGGPK3.dll`
   - Bundles2：`PatchBundle3`

POE1 的 Bundles2 英文表和本地化表必须通过同一次 `BundleExtractor --extract-list` 批量提取，英文 `BaseItemTypes` 是实时构建必需项；如果索引短暂被 Steam/杀毒软件占用，提取器会有限重试，避免连续启动原生提取器造成 `_.index.bin` sharing violation。游戏更新会覆盖已写入的虚拟资源，因此用户仍需在更新完成后重新运行；脚本始终从当前索引提取底板并校验结构，不绑定固定赛季 DAT。

## 同名元数据匹配

`BaseItemTypes` 允许多个元数据路径复用同一个英文或本地化显示名，例如普通物品与任务别名。价格匹配必须保留名称索引中的全部候选，并为每个候选生成一行补丁；不能使用单值字典让后出现的路径覆盖前一条。

国服数据优先按本地化名称匹配。若多个英文物品共用同一翻译，则使用数据源提供的 `engname` 过滤候选；没有足够英文信息时只保留安全的单一候选，避免跨物品串价。修改匹配逻辑时，应同时更新 `物价补丁/tools/build_poe2scout_price_patch.py`、`build/payload/build_poe2scout_price_patch.py` 及对应测试。

Issue #23 的官服回归检查使用最新版 `Content.ggpk`：修复前匹配 565 行，修复后 582 行；`Head of the King`、`Kulemak's Invitation` 和三种 Crisis Fragment 的重复元数据路径均生成价格，缺失列表为零。

## 还原流程

未显式传入 `-Poe2Dir` 时，还原器与更新器一样先显示目录选择窗口，并复用最近一次有效目录。确认后获取真实游戏目录级互斥锁；更新器内部触发自动回滚时会显式跳过子进程重复加锁，由父更新流程继续持有同一把锁。

Bundles2 模式更新前会生成 `真实还原物价补丁.zip`，备份当前 `Bundles2` 关键物理文件：`_.index.bin`、`_.index.high.bin`、`_.index.low.bin`、`.index.dbg` 和当时存在的 `LibGGPK3`。还原时首先验证并使用这个物理备份包，不要求先准备 .NET；替换后会核对精确文件集合，失败则自动恢复操作前状态。

普通 `还原物价补丁.zip` 仍会生成，用于记录干净 BaseItemTypes 和 Words 内容，但 Bundles2 真实还原不再用 PatchBundle3 写回这些资源来冒充还原。生成或刷新还原包时会拒绝带传奇价格标记的 `Words.datc64`，包括旧版独立行、Overlay 专用 `<<...>>` 和当前兼容标记。

GGPK 模式如果没有干净还原包，不从当前已修改 GGPK 反提取还原包，避免污染备份。GGPK 与 Bundles2 逻辑还原都会读回目标 DAT 校验；逻辑写入校验失败会自动重试一次。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\物价补丁\tools\update_price_patch.ps1 -Poe2Dir "<POE2游戏根目录>" -NoInstall -NoPoe2dbFallback

powershell -NoProfile -ExecutionPolicy Bypass -File .\物价补丁\tools\restore_price_patch.ps1 -Poe2Dir "<POE2游戏根目录>" -NoInstall
```

## 构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build\make_release.ps1
```

构建发布版前需要准备还原种子包，优先放在项目内 `restore-seeds/`，也兼容放在仓库父目录：

```text
restore-seeds/
├── 国服还原包.zip
└── 国际服还原补丁.zip
```

这两个 zip 是发布构建的受控输入，已纳入仓库；游戏版本更新后必须从已确认干净的 WeGame 与国际服 Bundles2 刷新，并与代码一同提交：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build\refresh_restore_seeds.ps1 `
  -ChinaGameDir "<国服游戏根目录>" `
  -IntlGameDir "<国际服 Steam 游戏根目录>"
```

刷新脚本会批量提取全部受支持语言的 BaseItemTypes、Words、EndgameMaps，拒绝活动物价/岛屿标记后再原子替换种子包。

发布包在 `tools/downloads` 内携带固定 SHA512 的 .NET 8.0.28 离线修复 ZIP，运行时缺失时优先本地原子恢复，修复包也不可用时才访问 Microsoft 源。Python 自动修复依次使用华为云、阿里云、南京大学和 Python 官方备用源。镜像与官方源共用版本固定的 SHA256/SHA512，只有校验通过的 ZIP 才会进入原子安装阶段；发布版正常情况下不需要联网下载运行时。
