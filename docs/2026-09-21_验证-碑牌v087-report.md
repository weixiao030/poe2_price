# v0.8.7 碑牌名称价与裂痕文本修复

用户反馈 v0.8.6 游戏内出现多余的“底材参考”行和裂痕描述末尾 `]`，要求名称直接追加价格。本次重新提取并分析 `D:\poe2\Content.ggpk`，修改补丁生成与清理逻辑，实际安装、读回、故障跳过和还原均通过。碑牌仍默认随通货更新，魔法与稀有词缀分别标价，保留岛屿传言。验证范围是文件内容、引用、索引、程序流程与打包程序启动；没有启动游戏进行画面验收。

本次实际写入与发布已获用户明确授权。测试材料位于本地 `verification/tablet-v087/`；原始游戏资源没有提交到仓库。

## 证据、结论与修复

| 证据 | 结论 | 修复路径 |
|---|---|---|
| E-01：真实 BaseItemTypes 的 4396–4403 行，每类碑牌只有一个名称指针；名称位于行偏移 32，继承位于 40 | 魔法、稀有共用底材名称，不能按稀有度给同一名称字段写入不同整件报价 | `poe2_tablet_prices.py::price_tablet_names` 精确匹配 8 类 metadata，复用现有名称追加逻辑，使用 poe.ninja `Normal` 底材报价 |
| E-02：原始 `map_unstable_breach_enrage_x_additional_rare_monsters` 的两条繁中描述以 `怪物]` 结尾 | 多余括号来自原始资源，原有单数、复数及未报价分支均需要清理 | `clean_chinese_markup` 仅移除中文描述未配对的右括号，保留 `[ContainsBreach\|裂痕]` 和 `[Rarity\|稀有]` 等成对链接 |
| E-03：v0.8.6 在使用次数描述追加“普通 / 魔法 / 稀有”目录行 | 该行不符合用户要求的名称标价方式 | 删除整个目录行生成逻辑；词缀仍由每类独立 IT/CSD 逐条标价 |
| E-04：实际安装后的中英文表都有名称价；仅清继承无法清除新名称价 | 关闭、跳过、缓存回退和还原可能残留旧价 | `poe2_tablet_refs.py::clean_tablet_layer` 仅清理已知 8 类碑牌的价格后缀与自有继承；中文核心生成、英文清理、缓存及还原共用 |

E-01、E-02 的原始提取文件为 `source/000000.bin` 至 `source/000005.bin`，安装后的提取内容位于 `installed-source/`；E-03 可对比 v0.8.6 的生成器；E-04 对应 `failure.log`、`skip-readback.log`、`restore.log` 与 `restored-source/`。由于本地副本含游戏数据，第三方需从自己获授权的同版本游戏提取，不能仅从 Git 仓库复现原始 DAT。
