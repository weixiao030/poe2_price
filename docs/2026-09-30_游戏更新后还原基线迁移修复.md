# 游戏更新后还原基线迁移失败修复

## 报错与根因

玩家截图先报告旧真实还原包过期（`Bundles2/Tiny.V0.1.bundle.bin` 长度变化），随后报告“清理迁移校验失败：BaseItemTypes.datc64 仍包含物价补丁标记”。旧还原包过期本身是正常保护，失败发生在重建干净基线的过程。

碑牌名称价和词缀价从普通更新范围独立后，清理调用仍只传 `--patch-scope none --no-uniques --strict-feature-cleanup`。构建器默认开启碑牌两层，因此会请求行情，并在清理旧价之后重新写入碑牌价格。后续严格校验正确拒绝了这份含价基线。

三个受影响入口均已补充 `--no-tablet-prices --no-tablet-affixes`：

- 更新器 `New-CleanPhysicalRestoreZipFromPatchedSources`：Bundles2 物理基线迁移。
- 更新器 `New-CleanLogicalRestoreZipFromPatchedSources`：逻辑还原基线迁移。
- 还原器 `New-Poe2RestoreBaselineFromCurrentGame`：还原时自动重建基线。

普通更新中的 `scope=none` 仍允许用户独立开启碑牌价格；没有改变这个行为，也没有放宽旧还原包、结构签名或价格残留校验。

## 本地资源验证

只读提取用户指定的 WeGame 和独立客户端资源，并在工作目录中清理和复现，没有安装补丁到真实游戏。

| 客户端 | 有效名称行数 | 当前检测命中 | 旧迁移参数加模拟行情后 | 修复后 |
| --- | ---: | ---: | ---: | ---: |
| WeGame 简体中文 | 5079 | 0 | 8 条碑牌价 | 0 |
| 独立端繁体中文 | 5072 | 480 | 8 条碑牌价 | 0 |

“当前检测命中”使用原 PowerShell 检测规则，不能视为所有已标价名称的总数。国际服实际清理了 620 个普通名称价格和 428 个 Words 价格。两客户端清理前后的 BaseItemTypes 结构签名完全相同，清理后的行情请求次数为 0。旧参数对照使用有效的离线模拟行情，未依赖外部 API 当时是否可用。

本机 WeGame 当前资源干净，已有还原包记录的 39 项官方底板信息全部匹配，因此没有触发玩家的陈旧备份迁移分支。这解释了本机正常与玩家报错可以同时出现。

另外直接执行修复后的物理迁移函数，使用真实 WeGame 索引的沙盒副本：PatchBundle3 替换两项资源，原读回校验通过，成功生成含 17 个恢复文件的 v2 `semantic-clean-migration` 还原包。真实游戏的索引/LibGGPK3 内容指纹和官方底板指纹在验证前后均一致。
