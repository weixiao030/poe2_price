# 1.0.10 配置与碑牌开关验证

## 项目链路与本次行为

桌面端为 Electron + Vue / Pinia，界面通过预加载 IPC 调用主进程；主进程负责请求校验、配置持久化、游戏目录确认、任务互斥与自动更新调度。worker 调用 PowerShell 安装流程，Python 获取行情并生成游戏资源，安装工具写入 GGPK 或 Bundles2 后读回校验。运行环境、用户配置、引擎输出与游戏备份独立于安装目录，软件升级复用用户数据目录。

使用 impeccable 布局检查流程，遵循“现有样式不要变”：保留配色、字体、侧栏、卡片、按钮和开关，只调整赛季位置、范围排列与配置分组。新增碑牌价格、碑牌词缀价格独立开关，补丁功能选项默认全开；保留每小时自动更新默认关闭的行为。

配置修改通过串行保存队列落盘，显示保存状态，保存期间不允许开始补丁操作。缺少新字段的旧配置按开启处理，显式关闭不被默认值覆盖。底材价格与词缀价格随通货范围生效，暗金碑牌价格随传奇范围生效，不适用的范围保留用户偏好。

自动更新以首次手动成功确认的游戏目录、安装类型作为边界，执行时读取最新保存的范围、碑牌开关、岛屿提示、语言和对应服区赛季。切换到尚未确认的客户端会暂停；普通配置修改不会把原定更新时间不断推迟。旧配置没有赛季偏好时沿用已确认的赛季。

碑牌名称和词缀分别获取、生成和记录状态。关闭选项在下一次成功更新时清理旧名称、暗金价签或词缀引用；英文过滤器名称保持原值。四种开关组合使用独立缓存。关闭碑牌价格时禁用可能保留旧暗金价签的部分资源缓存回退，避免报告成功却留下关闭项目。

## 真实客户端文件验证

国际服官方 GGPK 与国服 WeGame Bundles2 使用真实行情接口、打包后的 worker 和安装工具。各场景更新后重新提取游戏中的资源，与生成的补丁逐资源比较 SHA256，并检查活跃名称、暗金价格、碑牌继承引用及英文过滤器名称。

七个连续场景：全部开启、仅名称价格、仅词缀价格、全部关闭、仅保存新偏好后重启自动更新、还原、重新全部开启。自动更新场景只在隔离测试配置中把截止时间设为已到期，让真实调度器自然触发，不替换 worker 或行情结果。

| 场景 | 国际服官方 GGPK | 国服 WeGame Bundles2 |
| --- | --- | --- |
| 全部开启 | 通过 | 通过 |
| 仅碑牌价格 | 通过 | 通过 |
| 仅碑牌词缀价格 | 通过 | 通过 |
| 全部关闭及旧标注清理 | 通过 | 通过 |
| 保存新配置后重启自动更新 | 通过 | 通过 |
| 还原及清理读回 | 通过 | 通过 |
| 再次全部开启 | 通过 | 通过 |

两客户端均完成 7/7 场景，最后保留全开补丁。国际服全开写入 8 类碑牌底材、8 个词缀资源及 434 条传奇；关闭碑牌价格后传奇为 425 条，9 种暗金碑牌旧价签清除。国服全开写入 8 类碑牌底材和当前有报价的 5 种暗金碑牌；关闭碑牌价格后对应旧标注清除。每个场景的结果、生成摘要、资源哈希和语义检查分别保存在本地 `verification/preferences-v1010/international/` 与 `verification/preferences-v1010/china/`。

这是实际客户端文件写入、读回和真实桌面界面的验证；没有启动游戏，因此不包含游戏内悬浮提示截图或实际游玩验收。国际服部分词缀交易条件无法精确匹配时按既有规则保留无价或采用可用单侧报价，日志记录降级原因。

国服数据源部分词缀缺少中位价，沿用既有的可校验最低价兜底；一组无行情词缀保留原文，过期汇率继续使用同赛季有效值。这些行情状态已记录在生成报告中。
