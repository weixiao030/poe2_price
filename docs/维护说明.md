# 维护说明

当前唯一入口位于 `desktop`。按根 README 构建和测试；所有发行核心文件由 `docs/core-provenance.json` 追踪，变更原引擎时应同时更新来源说明并运行对应回归。

发布：保持 `desktop/package.json` 与 lockfile 版本一致，先通过 main 的 Build Desktop Release，再推送对应 v 标签。1.0.0 起只发布安装版及更新元数据。标签构建通过后签名 latest.yml，先上传并验证 ZOS，再创建 GitHub Release；两端使用相同文件。CI 需要 UPDATE_PRIVATE_KEY、ZOS_ENDPOINT、ZOS_BUCKET、ZOS_CREDENTIALS，缺失时发布失败，不发布缺少签名或备用源的正式版本。

长期更新契约见 [1.0.0 安装版与在线更新设计](1.0.0安装版与在线更新设计.md)。不要为每个旧版本增加增量包或程序文件基线；保持 appId、安装身份、用户数据位置和标准更新元数据格式稳定。
