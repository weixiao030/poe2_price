# 碑牌魔法／稀有分价：原方案无效，实验已撤销

当前需求尚未完成。两套 API 报价可以分别获取和离线生成，但现有 `.it` 的重复 `stat_description_list` 不能按稀有度选择不同 CSD。读取磁盘客户端的字段处理函数后，已确认它覆盖同一个资源引用，`enable_rarity` 只设置稀有度位标志。此前实验曾真实写入并通过字节读回，随后已经撤销；2026-09-22 00:55 的再次只读核对确认游戏恢复至实验前索引与基础表。不能将报价匹配、压缩包完整性或写入读回成功表述为游戏分价成功。

分析范围见 [scope.md](../verification/final-tablet-build/static-client/scope.md)。只访问游戏文件，未访问游戏进程内存，未注入、修改或执行客户端 EXE；报告为普通功能分析，flavor=null。

## 文件中的明确证据

样本为 `D:/poe2/PathOfExile.exe`，SHA-256：

```text
dc3b3f1bedbf664a21fb71ff6fd178db5e55f588efc53ead026a87d963468714
```

使用本机 `pefile` 读取 PE 节、导入表、异常函数边界，并用 `capstone` 解码相关函数。IDA 技能的启动脚本返回未安装 IDA，实际分析工具为上述文件解析库，未声称执行过 IDA 反编译。导入表有 26 个 DLL、519 个导入，完整列表与网络、文件、注册表、加密、进程 API 分类保存在 `survey-imports.json`；这些是磁盘静态数据，不是运行时调用记录。

`Mods` 字段处理函数位于首选映像地址 `0x1421e0880`。地址只适用于上述样本哈希：

| 字段 | 关键指令／数据 | 结论 |
|---|---|---|
| `stat_description_list` | `0x1421e0905 lea rcx,[rsi+0x38]`；`0x1421e0922 mov [rcx],rax`，并在后续同样设置 `+0x40` | 单个资源句柄赋值；旧句柄引用计数被递减，没有按 rarity 索引数组 |
| `mod_stat_description_list` | `0x1421e09fb add rsi,0x40`；`0x1421e0a14 mov [rsi],rax` | 另一个单独的描述引用，亦无稀有度分派 |
| `enable_rarity` | `0x1421e0abf / 0x1421e0b2f / 0x1421e0b9f / 0x1421e0c05` 对 `[rsi+0x49]` 分别 OR `1/2/4/8` | 启用普通、魔法、稀有、传奇的标志；不存储描述路径 |
| `disable_rarity` | 同一字节分别 AND `0xfe/0xfd/0xfb/0xf7` | 清除相应标志，与描述资源引用独立 |

完整函数汇编见 [0x1421e0880.asm](../verification/final-tablet-build/static-client/0x1421e0880.asm)。当前 GGPK 的 287 个 `.it` 中，42 个含该描述字段，没有任何模板重复配置该字段。这是辅助证据；否定四列表方案的主要依据是客户端的单句柄赋值逻辑。

据此，顺序写入“普通、魔法、稀有、传奇”四条路径不能建立四个独立槽位。即便全部文件都成功写入、路径都能提取，也没有实现所需分流。此次只否定这个具体实现，没有对所有可能的客户端文件方案作不可能性证明。

## 项目收尾修改

- 保留独立魔法／稀有 API 请求；拒绝稀有度不匹配或未标明稀有度的响应。默认仍拒绝过期快照。
- 删除错误的四列表生成器；在没有可靠分流实现时写入明确的 skipped 报告并抛出异常，原待安装 ZIP、DAT 不变。上层继续使用已有的碑牌失败隔离流程。
- 资源引用校验拒绝重复的 `stat_description_list`。撤回仅为无效方案新增的 native 安装器路径白名单，恢复该 EXE 至当前 Git 版本。
- 同步桌面运行资源、provenance 与 manifest 哈希。
- 原实验 ZIP 保留原始字节，改名为 `.zip.rejected`，在证据目录明确标记不可安装；没有发布这些实验产物。
- `python -X utf8 -m pytest tests -q`：**297 passed**。测试验证防混价、失败隔离和打包一致性，不代替游戏显示验证。
