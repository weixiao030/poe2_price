# 1.0.0 安装版与在线更新设计

本设计用于 1.0.0 重构：Windows x64 只发布 NSIS 完整安装包，采用稳定版 electron-updater。1.0.0 及后续客户端读取同一格式的最新发行元数据，直接升级到最新版本，无需经过中间版本，也无需为旧版逐一构建升级包。实现与实机结果见 [1.0.0 验收记录](2026-09-23_v1.0.0安装版重构验收.md)。

## 联网参考与选型

2026-09-22 核对官方文档、固定版本源码及 npm 稳定标签。

| 方案 | 官方机制 | 本项目选择 |
| --- | --- | --- |
| Electron 内置 autoUpdater / Squirrel.Windows | 使用 RELEASES、完整 nupkg 和可选差分包 | 需要更换现有 NSIS 安装体系 |
| electron-builder / electron-updater | NSIS 完整安装包、latest.yml、blockmap；差分失败回退完整下载 | 采用，沿用已有安装体系和界面 |
| Velopack | UpdateManager、完整发行包和可选 delta；无基线或差分失败时下载完整包 | 能满足需求，但需要额外迁移打包、启动钩子和安装结构 |

参考来源：

- [Electron 官方更新指南](https://www.electronjs.org/docs/latest/tutorial/updates)：内置 autoUpdater 使用 Squirrel，静态对象存储可以承载更新，不需要自建业务服务器。
- [electron-builder 26.15.3 更新文档](https://github.com/electron-userland/electron-builder/blob/electron-builder%4026.15.3/website/docs/features/auto-update.md)：Windows 的自动更新目标是 NSIS；支持下载进度和多种发布后端。
- [electron-updater 6.8.9 下载实现](https://github.com/electron-userland/electron-builder/blob/electron-updater%406.8.9/packages/electron-updater/src/AppUpdater.ts)：differentialDownloadInstaller 捕获差分失败并回退完整安装包。
- [electron-updater 6.8.9 安装实现](https://github.com/electron-userland/electron-builder/blob/electron-updater%406.8.9/packages/electron-updater/src/NsisUpdater.ts)：下载并核验安装包，调用 NSIS 安装器。
- [Velopack 集成文档](https://github.com/velopack/velopack.docs/blob/master/docs/integrating/overview.mdx)：无本地基线、差分不可用或重建失败时下载完整发行包。
- [Velopack 差分说明](https://github.com/velopack/velopack.docs/blob/master/docs/packaging/deltas.mdx)：构建时可根据上一发行生成差分。
- [Squirrel.Windows 项目说明](https://github.com/Squirrel/Squirrel.Windows)：安装和更新使用 NuGet 包。

固定依赖 electron-updater 6.8.9、electron-builder 26.15.3；不采用当前 next 标签下的 7.x / 27.x 预发布 API。依赖升级另行验证，不与每次业务版本发布绑定。

业务版本日常发布只需构建当前版本。今后如果更换更新框架主版本、签名机制或安装身份，必须额外用已正式发布的 1.0.0 原包做兼容验证；当前自动测试用同一生产实现构建 1.0.0 / 2.4.0 的隔离应用，不能将它误称为未来未知协议变更的永久证明。

## 发布与跨版本更新契约

每次发布只构建一次完整 Setup.exe，附带 builder 生成的 blockmap、标准 latest.yml、latest.yml.sig 和 SHA256SUMS.txt。用户下载入口只有 Setup.exe；其余文件供更新器和校验使用。

latest.yml 保持标准 files 数组及 SHA-512 格式。构建阶段自动填入版本、文件大小、哈希和版本说明；维护者不手写元数据、不传入旧版目录。签名覆盖最终 YAML 字节。镜像和 ZOS 分发相同文件。

从 1.0.0 开始固定以下契约：

- appId 保持 com.poepricepatch.desktop，package.name、程序名、安装身份及用户数据目录保持稳定。
- Windows x64，按当前用户安装；程序文件与设置、缓存、日志、游戏还原备份分开存储。
- 所有正常更新都能下载完整目标安装包。不依赖历史程序文件哈希，不要求本地缓存完整，不要求逐版升级。
- blockmap 只用于节省下载量。缺少旧安装包缓存、旧 blockmap 被清理、服务器不支持 Range 等情况由框架回退完整下载。
- 不增加 fromVersion、每个旧版的文件清单、最低业务版本或逐版本路由。版本比较只用于判断目标是否更新。
- 新版本继续提供 1.0.0 能读懂的元数据字段及签名。升级构建工具时仍需通过固定协议的发布校验。
- 同一版本号对应唯一一组发行字节，发布后不可覆盖；修复必须提高版本号。

未来业务设置变化优先使用可选字段和默认值。确有数据结构变化时按独立数据 schema 迁移，并保留备份；这不影响安装包跨版本升级，也不生成软件版本之间的兼容分支。

## 下载顺序和信任

检查元数据和下载安装包分别按国内镜像顺序尝试，全部失败后才使用 ZOS。保持现有八个国内镜像和顺序，不新增 GitHub 直连回退。安装包地址固定到已验证版本的 GitHub Release，避免下载过程中 latest 指向另一版本。

源切换只更换传输地址，不改变已验证的目标版本和哈希。每个源有独立超时；用户取消立即终止整个下载。HTTP 错误、异常响应、签名不符、下载内容校验失败均可切换下一源。失败不会触发安装。

在标准元数据外附加 Ed25519 分离签名 latest.yml.sig，沿用现有公钥与发布私钥。先验证 YAML 原始字节，再交给框架使用。框架负责安装包 SHA-512 校验，安装前再次核验本地缓存，避免下载后缓存被修改。

国内镜像适配使用 electron-updater 的 Provider 扩展点。适配层只提供经过签名验证的标准 UpdateInfo 和目标地址；差分下载、完整下载、缓存及运行安装器继续交给框架，不再自行逐文件覆盖程序。

目前项目未配置 Windows Authenticode 证书。Ed25519 保留软件内在线更新的来源验证；今后接入 Windows 代码签名时启用框架的发布者签名校验，不将 SHA 校验误称为 Windows 代码签名。

## 安装时机与功能保留

保留当前检查更新、版本说明、下载进度、取消下载和重启更新入口。软件更新与每小时物价更新仍然独立。

关闭框架的发现即自动下载、退出即自动安装。用户选择更新后下载；准备安装时确认物价、汉化、还原、查询和清理任务均已结束。进入安装状态后禁止启动新任务，停止后台调度，交由 NSIS 完成安装并重启。关闭到托盘和系统关机不应意外触发更新安装。

保持现有设置、运行历史、赛季选择、自动更新计划、托盘、自启及游戏文件保护行为。软件升级不主动执行游戏补丁写入。

下载失败继续使用现有程序。NSIS / electron-updater 不提供“新版业务启动失败后自动恢复全部旧程序”的通用保证；保留更新结果记录，提供完整安装包修复路径。不能继续宣称旧自研逐文件安装器的事务回退能力由新框架原生提供。线上异常版本停止推广，并以更高版本号发布修复，避免自动降级破坏用户数据。

## 发布顺序

构建、签名和验收完成后，先上传 Setup 与 blockmap，核对可访问性和文件哈希，再上传签名元数据。GitHub 与 ZOS 必须使用同一组构建产物；版本文件不可覆盖，元数据使用短缓存或 no-cache。

保留历史安装包和 blockmap 有利于修复及差分下载，但它们不是完整升级的前提。CI 不重新构建并覆盖已有正式 Release。

0.x 使用旧 ZIP 更新协议，不能直接读取 latest.yml。旧用户通过 1.0.0 Setup 完成一次迁移；沿用用户数据目录。此边界只发生一次，从 1.0.0 起不再维护旧 ZIP 协议，也不为每个后续版本增加迁移包。

## 验收要求

先验证无旧基线的完整升级，再验证差分优化，避免只测试理想缓存状态。

1. 1.0.0 直接升级至跨多个小版本的目标，目标只发布一份安装包。
2. 首选镜像成功、切换备用镜像、全部镜像失败后使用 ZOS。
3. 清单签名损坏、安装包损坏、超时、取消、重试、下载后本地缓存变化均正确处理。
4. 无缓存及旧 blockmap 缺失可回退完整安装包；真实 NSIS 下载、安装、重启和安装身份验证通过。
5. 正在运行任务时禁止安装，准备安装期间无法启动新任务，普通退出不自动安装。
6. 安装后设置、历史记录、自动更新计划保留，物价、汉化、还原及原有桌面验证通过。
7. 构建只生成安装版，不再发布免安装 ZIP 或旧式专用增量 ZIP；真实安装包及发布清单通过校验。
