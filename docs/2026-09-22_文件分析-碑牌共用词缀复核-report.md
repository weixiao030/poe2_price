# 碑牌魔法／稀有：共用词缀，现有资源补丁不能自动分价

重新读取当前游戏文件后的结论是：**魔法和稀有碑牌共用同一套词缀定义。当前项目通过 DAT、IT、CSD 修改名称和词缀文本的方式，没有已验证的入口按物品自身稀有度选择两个价格。** API 可以分别查魔法、稀有行情，但不能仅把两套报价写入描述文件，就认为游戏会分别选用。

本轮只分析文件，没有改动游戏。分析范围见 [scope.md](../verification/tablet-reanalysis-20260922/scope.md)，原始提取、脚本、汇编和逐文件 SHA-256 均在 [证据目录](../verification/tablet-reanalysis-20260922/)。普通功能分析，flavor=null。

## 1. 当前游戏实际共用哪些记录

从 `D:/poe2/Content.ggpk` 新提取 338 个资源，包括 287 个 IT、35 个 CSD 以及英文／繁中 DAT。每份资源的长度和 SHA-256 均已独立复核。

| 检查对象 | 本轮结果 | 对分价的意义 |
|---|---|---|
| BaseItemTypes | 5,496 行，其中 8 行碑牌，均为 Domain 34、同一个碑牌物品类 | 每种碑牌一个底材记录，没有魔法版／稀有版两行底材 |
| Mods | 全表 16,784 行；碑牌域 135 行，其中 45 条 generation=3、13 条前缀、77 条后缀 | 普通随机前后缀共 90 条，不是各品质分别 90 条 |
| 可生成词缀 | 90 条中 86 条对当前八类底材有正权重，形成 254 个底材＋词缀组合 | 4 条零权重记录没有混入市场对应关系 |
| 生成条件 | 只使用 default 和各类 tower_augment 标签；这 90 条的 GenerationWeight 列表和额外 Tags 列表均为空 | 没有使用 magic／rare 标签区分两套词缀 |
| 词缀 Stat | 90 条显式词缀的第一 Stat 全部不同，没有同一第一 Stat 的魔法／稀有副本 | 同一效果直接引用同一条 Mods／Stats 定义 |
| 原始碑牌 CSD | 120 个 description，全部只声明 1 个 Stat 输入 | 数值条件中没有附带“物品自身品质” |

`Tags.datc64` 的确存在 `magic` 和 `rare` 标签，但碑牌词缀并没有引用它们作为生成条件。不能仅凭标签存在就推断碑牌有分价开关。

具体例子（DAT 行号从 0 开始）：

| 效果 | Mods 行／ID | Stats 行／ID | 数值 |
|---|---|---|---|
| 怪物效用 | 5097 / TowerMonsterEffectiveness1 | 24372 / map_monster_potency_+% | 10～15 |
| 怪物稀有度 | 5102 / TowerMonsterRarityIncrease1 | 25132 / map_number_of_magic_and_rare_packs_+%_and_rare_monster_modifiers_chance_% | 15～20 |
| 掉落物品稀有度 | 5098 / TowerDroppedItemRarityIncrease1 | 1239 / map_item_drop_rarity_+% | 8～12 |
| 祭祀重骰贡礼降低 | 5168 / TowerRitualRerollCostIncrease | 13227 / map_ritual_rewards_reroll_cost_+%_final | -30～-20 |

以上三种含“效用／稀有度”的属性不是同一个 Stat。`TowerRitualRareMonsters` 等 ID 内的 Rare/Magic 也不能当作碑牌品质，相关 Stat 描述的是怪物。

完整记录见 [tablet-mods.tsv](../verification/tablet-reanalysis-20260922/tablet-mods.tsv) 和 [tablet-mods.json](../verification/tablet-reanalysis-20260922/tablet-mods.json)。解码使用已核实字段偏移，检查 DAT 行宽、外键、数组边界与权重数量；未强套最新 schema 的未知尾部字段。

## 2. 现有价格文件为什么不能按品质切换

当前游戏已经装有此前的价格补丁。8 个底材分别继承 `Metadata/Items/TowerAugments/Poe2Price/...`，每个 IT 只指定一份 CSD，同时启用 normal、magic、rare、unique。实际链路逐份读取保存在 [verified-result.json](../verification/tablet-reanalysis-20260922/verified-result.json)。

例如祭祀碑牌的当前描述为：

```text
stat_description_list = "data/statdescriptions/poe2price/ritual_tablet_stat_descriptions.csd"
enable_rarity = "magic"
enable_rarity = "rare"
```

该 CSD 中怪物效用的繁中价格条件是：

```text
1 map_monster_potency_+%
10|15 "增加{0}%怪物的[MonsterEffectiveness|效用]=41.8E"
```

重骰贡礼的价格条件是：

```text
1 map_ritual_rewards_reroll_cost_+%_final
-30|-20 "減少{0}%地圖內的[ContainsRitual|祭祀神壇]重骰所需的貢禮數量=35.8E" negate 1
```

这些是**当前磁盘文件中的旧价签**，不是本轮新增报价。魔法和稀有碑牌只要进入同一词缀、同一数值区间，就使用同一个条件；该条件并没有第二个稀有度输入。

磁盘客户端静态核实进一步说明了限制。样本为 `D:/poe2/PathOfExile.exe`，SHA-256：`dc3b3f1bedbf664a21fb71ff6fd178db5e55f588efc53ead026a87d963468714`。以下地址只适用于此样本的首选映像地址，未读取运行中进程：

| 函数／位置 | 静态证据 |
|---|---|
| `0x1421e0880` | `stat_description_list` 覆盖单个描述句柄；`enable_rarity` 修改独立位标志。前轮结论本轮重新定位确认，仍不能把重复字段与四种品质配对 |
| `0x1421e33b0`，`0x1421e351d`、`0x1421e353b` | 输出 `rarity` 字段时单独读取实例属性，再调用通用稀有度名称转换；实例品质确实存在，但不是 CSD 自动可见的参数 |
| `0x1426008b0` | CSD 顶层解析 description、include、lang、handed_description、has_identifiers、no_identifiers、no_description；未见稀有度分支语法 |
| `0x1426738b0` | description 声明的输入名称在 Stats 表中查找；不存在时走 `Stat does not exist in Stats table` 错误路径 |
| `0x142672860` → `0x14267a780` | 对每个声明的 Stat 读取数值条件；后者解析 `!` 和 `|`，保存区间上下界与反转标志，不是任意物品属性表达式 |

因此，不能直接在 CSD 中自行加 `rarity`、`item_rarity` 或 `local_item_rarity`：当前 Stats 表没有这几个精确名称。`map_rarity`、`monster_rarity` 虽然存在，但碑牌 Mods 没有提供它们，碑牌描述也没有使用它们。本轮没有证明它们会在碑牌物品的描述上下文中被自动填入，不能拿它们作为可安装方案。

此外，`ObjectMagicProperties` 不是可凭名字认定的“魔法碑牌专用入口”。当前 287 个 IT 没有使用该组件；其描述字段仍只保存一个句柄，静态诊断函数还会读取自身 rarity 并调用通用转换函数。不能把它与稀有物品分配两份 CSD 的功能混为一谈。

这说明**当前资源补丁没有满足要求**，不等于对所有可能的客户端代码改造作不可能性证明。要实现自动分价，必须先证明描述选择或格式化阶段能够取得碑牌自身品质，并将其可靠接入报价选择。本轮没有发现已可用的资源配置方案。

## 3. API 与游戏词缀的对应核查

用户提供的 API 本轮分别请求 magic／rare，各返回 254 条。两个列表 ID、碑牌类型、前后缀类别、英文名称和文本逐项对上；根据底材生成条件、前后缀类型、游戏 CSD 文本及名称，254 个条目均找到唯一游戏词缀候选，零歧义。此检查确认**报价条目的声明含义**，不等于已经验证每个交易查询的取样都精准一致。

解压 API 返回的交易查询后：

- 244 对查询去掉 rarity 后完全一致。
- **10 对除 rarity 外还有词缀查询范围差异**：一边筛选单一 explicit ID，另一边以 count≥1 允许两个 explicit ID 中任意一个。涉及额外精魂、保险箱、精髓、神殿。这些查询的取样范围不能直接视为相同。
- 例：总督碑牌“额外 1 个精髓”的魔法查询同时允许 `explicit.stat_2162684861` 和 `explicit.stat_395808938`，稀有查询仅允许后者。同一总督底材另有“额外 1～2 个精髓”的独立游戏词缀；不能未经核实就把这类 OR 查询认定为精确报价。

完整对应与查询差异见 [api-game-correspondence.json](../verification/tablet-reanalysis-20260922/api-game-correspondence.json)。这 10 对是实际发现的上游查询差异，未修改接口，也未将它们写入游戏。

一个查询范围一致的实例是深渊碑牌怪物稀有度：两边均用 `explicit.stat_4142653832`，只是 type_filters 的 rarity.option 分别为 magic／rare。这清楚区分了“相同词缀定义”和“不同品质市场行情”。

本次两套快照均标记 stale=true：magic=`eb030eee631448f8f8da5740`，rare=`f3193da93486cfd1df68c40a`。它们仅用作结构与对应关系分析，不作为实时行情安装。

本轮没有修改生产代码、GGPK 或游戏 EXE，没有访问游戏进程内存，没有声称完成游戏界面分价实测。新增内容仅为本轮证据、分析脚本和报告。当前 GGPK 索引 SHA-256 仍为：

```text

```
